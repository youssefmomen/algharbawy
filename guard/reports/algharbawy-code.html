خطرالدخول بيحوّل لأي رابط تحط في next (إعادة توجيه مفتوحة)

فين بالظبط: ملف assets/auth.js، السطور 6-8 و45

function next() {
    return new URLSearchParams(location.search).get("next") || "index.html";
  }
  ...
  if (u) location.href = next();

إيه الغلط: الصفحة بتاخد قيمة next من الرابط وتروح لها بعد الدخول من غير أي تحقق.

إيه اللي كان ممكن يحصل (شرح دفاعي): حد يبعت لضحية رابط للموقع الحقيقي، لكن بقيمة next بتشاور على موقع تاني مزيّف أو على رابط من نوع javascript. الضحية بتشوف رابط موثوق، تسجل دخول، وبعدها تتحول لصفحة المهاجم (تصيّد)، وفي حالة javascript ممكن ينفذ كود في صفحة الموقع. (CSP اللي اتضاف بيقفل جزء التنفيذ، لكن التحويل الخارجي كان ممكن.)

الحل بالظبط: اقبل بس اسم صفحة داخلية: if (/^[A-Za-z0-9_-]+\.html(\?[A-Za-z0-9_=&%.-]*)?$/.test(n)) استخدمه، وإلا index.html.

الحالة: تم الإصلاح في الطلب القادم (PR جديد) في assets/auth.js.

تحسيننقاط الخبرة والنجوم يكتبها المتصفح من غير حدود

فين بالظبط: ملف assets/store.js السطور 57-62 + firestore.rules السطور 33-37

db.collection("progress").doc(uid).set({ xp: stats.xp || 0, stars: stats.stars || {} }, { merge: true })
// rules: allow create, update: ... hasOnly(['completed','xp','stars'])

إيه الغلط: القواعد بتتأكد من أسماء الحقول بس، مش من نوع القيمة ولا حجمها. أي طالب مسجل يقدر يكتب أي رقم في xp.

إيه اللي كان ممكن يحصل (شرح دفاعي): طالب فاهم بيفتح أدوات المتصفح ويبعت xp بقيمة ضخمة لنفسه، فيطلع الأول في أي ترتيب، أو يملأ المستند بنص كبير يستهلك حصتك المجانية.

الحل بالظبط: في firestore.rules أضف شروط: request.resource.data.xp is int && request.resource.data.xp >= 0 && request.resource.data.xp < 1000000، وstars is map، وcompleted is list وحجمها أقل من 2000.

الحالة: يحتاج نشر القواعد من Firebase Console (المرحلة التانية). مش اتغير دلوقتي.

تحسينالتحقق من المدير بالبصمة داخل الكود

فين بالظبط: ملف assets/firebase-config.js السطر 12 + assets/store.js السطور 88-95

adminEmailHash: "733c5628...6bb4b28"  //  hex === cfg.adminEmailHash

إيه الغلط: الإيميل نفسه اتشال، لكن البصمة (SHA-256) ظاهرة للعامة، وده فحص على جهاز الزائر. ده بيحدد هل تظهر لوحة المدير، مش هل البيانات متاحة.

إيه اللي كان ممكن يحصل (شرح دفاعي): حد يجرب بصمات إيميلات متوقعة ويعرف إيميل المدير، أو يعدل الفحص في متصفحه عشان تظهر له واجهة الإدارة (لكن بدون بيانات لو القواعد متظبطة).

الحل بالظبط: اعتمد على مستند admins/{uid} في Firestore فقط واحذف adminEmailHash بعد إنشائه، والقواعد هي اللي تحمي البيانات.

الحالة: مؤقت، مرتبط بالمرحلة التانية (إنشاء مستند الأدمن ونشر القواعد).
